## 2026-09-29 — 설계와 첫 동작

**출발점.** 수익 자동화 파이프라인(유튜브 제작 자동화)을 돌리면서 여러 에이전트 탭을 사람이 직접 오가며 지시·전달하는 방식이 병목이 됐다. "회장은 CEO에게만 말하고, CEO가 팀을 꾸려 운영한다"는 구조로 새로 만들기로 했다.

**설계 초안 v2.1과 리뷰.** 오케스트레이터 설계를 두 독립 리뷰어(다른 모델 계열 1, 새 Claude 세션 1)에게 검토받았고 둘 다 **NO SIGN**. 주요 지적:
- CEO가 직접 분석·문서를 쓰면 스스로 검증하는 셈이 된다 → CEO는 판단·배정만, 초안은 작업자가 쓴다.
- 작업자의 "완료" 주장과 종료 코드 0을 믿으면 안 된다 → 완료 계약 파일 + 하네스가 직접 재검증.
- 승인은 대상이 바뀌면 무효여야 한다 → 계획 해시에 묶고 만료를 둔다.

**스택을 실측으로 결정.** 펫·데몬 후보를 같은 맥에서 띄워 메모리를 쟀다 → [0002](decisions/0002-stack.md). Swift 펫 약 15MB, TypeScript 데몬.

**데몬 1차.** SQLite(WAL) 저장소, SSE 이벤트 버스, 팀 스케줄러(종료 코드 계약: 0 한가/3 대기/75 한도/그 외 오류), 127.0.0.1 전용 + Bearer 토큰 + Origin 거부.

**CEO 턴.** `claude -p`를 읽기 전용 도구(Read/Glob/Grep), JSON 스키마 출력, 세션 재개로 호출. 출력은 "질문 ≤3개" 또는 "계획+작업 지시서" 중 정확히 하나 → [0004](decisions/0004-ceo-turn.md).
첫 실제 요청 "펫 말풍선 글자 크기를 설정 파일에서 바꿀 수 있게"에 대해 L1 등급, Sonnet 구현+검증 계획을 $0.38에 생성, 승인 대기까지 확인.

**펫.**
- 처음엔 모든 팀을 걸어다니게 했더니 산만했다 → 바쁘거나 결정이 필요한 캐릭터만 표시, 걷기 제거, 드래그 위치 기억.
- CPU 10.5% → 변경 시에만 갱신, 바쁜 캐릭터만 애니메이션, 12fps 타이머로 **약 2.5%**.
- `open`으로 실행하면 안 보이는 버그: 바탕화면 폴더의 토큰을 메인 스레드에서 읽다 macOS 권한 창에 막힘 → 토큰을 `~/.config/hq`로 이동.
- 다른 도구(Orca) 세션까지 펫에 띄웠다가 "hq는 Orca와 완전히 별개여야 한다"는 피드백으로 해당 기능 제거.

**이전 하네스의 교훈 재검토.** 회사에서 만들었던 멀티 에이전트 하네스의 운영 기록을 전부 다시 읽고, 개인 환경에 옮길 원칙을 정리 → [0005](decisions/0005-lessons-from-previous-harness.md).

## 2026-09-30 — 실행 엔진과 첫 완주

**실행 계약을 먼저 정했다.** 작업자를 실제로 돌리기 전에 계약 문서([execution.md](design/execution.md))를 쓰고 두 독립 리뷰어에게 두 번 검토받았다(v1 → v2 → v3). 굵직한 판정:
- 작업자가 쓸 수 있는 저장소에서는 hq가 git을 아예 실행하지 않는다. 작업 결과는 hq 전용 미러로 fetch해서 별도 worktree에서 검사·검토·통합한다(훅·fsmonitor·replace 객체로 hq를 속이는 경로 차단).
- 작업자·검토자·검사 명령은 전부 macOS Seatbelt 안에서 돈다. 비밀 파일, hq 토큰·DB, 다른 작업자 경로, hq 제어 포트, `open`/`osascript`를 막는다.
- "기준선에서도 실패했으니 통과"라는 면제를 없앴다. 검사는 단일 명령, 수락 기준은 new/regression으로 구분.
- 모든 결정은 revision·generation으로 묶어, 늦게 온 응답이 새 상태를 덮지 못하게 했다.

**설계는 오케스트레이터, 구현은 작업자.** 엔진·웹·펫·CLI 네 갈래를 병렬 작업자에게 맡겼다. 지시서에는 위치·인터페이스·동작·테스트 케이스까지 적고 코드 본문은 적지 않았다. 막히면 설계를 바꾸지 말고 BLOCKED로 보고하게 했다. hq 안의 사장도 같은 규칙으로 지시서를 쓴다(`skills/ceo.md`).

**첫 실제 실행에서 나온 문제.**
- 샌드박스가 `~/.hq` 메타데이터까지 막아 모든 검사가 EPERM → 메타데이터 읽기는 허용.
- 기준선 면제 때문에 실패한 검사가 통과로 표시 → 면제 제거.
- 검토자가 적은 실행 테스트를 부분 문자열로 대조해 다른 명령과 짝지어짐 → 정확히 일치로 변경.
- 작업자가 커밋을 못 함(`--allowedTools` 누락), 키체인 차단으로 구독 인증 실패, git ref에 `~` 사용 → 각각 수정.

**첫 완주.** 연습 저장소에 "slugify 함수 추가" 요청: 사장 계획(단일 명령 검사 5개) → 승인 → Sonnet 작업자($0.064) → hq 검사 5/5 → 새 Sonnet 검토자($0.038, `npm test` 실행 확인) → 펫에 "확인해 주세요" → 수락 → `merge --ff-only` → 테스트 2/2 통과.
테스트는 단위 48 · 웹 25 · CLI 56개.

## 2026-09-30 — hq가 hq를 고치다 (dogfood)

자동 시작(launchd)을 설치하고, hq에게 hq 자신의 저장소를 맡겼다.

**1차: 펫 말풍선 글자 크기 설정.** 사장이 설정 파일을 저장소 밖(`~/.config/hq/pet.json`)에 두자고 스스로 판단했다(데스크탑 폴더 권한 창·설정 검증 예외를 피하려고). 지시서에 위치·규칙·테스트 13가지 경우까지 적었고, Sonnet 작업자가 그대로 구현해 병합됐다. 하지만 결과를 다시 확인하다 엔진의 구멍 세 개를 찾았다.
- **환경 실패를 "기존 실패"로 분류**: 의존성이 없는 복제본에서 `tsc`가 exit 127, 인자 없는 `node --test`가 목업 서버까지 실행해 시간 초과 → 둘 다 "원래부터 실패"로 처리돼 검사 없이 통과. → 환경 실패(setup 실패·시간 초과·126/127)는 작업자를 띄우기 전에 멈추고, 기존 실패도 후보에서 반드시 실행하도록 바꿈(계약 §9).
- **작업자 커밋에 개인 이메일**: 작업자 복제본이 프로젝트의 로컬 git 신원을 물려받지 못함 → 복제 직후 프로젝트 신원을 복사. 공개 전에 발견해 기록을 고쳤다.
- **검토 없음 + 기존 실패 = 판정자 없음** → 이 경우 검토자를 자동으로 붙임.

**2차: 중첩 샌드박스.** hq의 테스트는 내부에서 `sandbox-exec`와 `ps`를 쓰는데, 작업자는 이미 샌드박스 안이라 macOS가 둘 다 막았다(일부 실패, 일부는 영원히 대기). 여기서 실제 버그도 나왔다: `ps`가 실패하면 이미 뜬 작업자를 "시작 실패"로 기록해 추적을 놓친다. → ps 실패에도 작업자를 기록, 테스트는 샌드박스 안에서 격리 시험만 건너뛰고 나머지는 가짜 래퍼로 실행.

**3차: 검증 요청(상황 문장의 "sonnet가" 같은 어색한 조사).** 사장이 새 규칙대로 `npm test`·`npm run check`를 검사로 골랐고, 의존성 설치 → 작업 → hq 검사 7개(전체 테스트 포함) → 검토 → 수락 → 병합까지 **5분**. 작업자 커밋 작성자도 프로젝트 설정(noreply)으로 들어갔다. 격리 시험 10개는 샌드박스 밖에서 따로 돌려 166/166 통과를 확인했다.

## 2026-09-30 — 수익자동화 파이프라인을 hq 팀으로

콘텐츠 파이프라인(비공개 저장소)을 hq의 반복 팀으로 연결했다.
- 팀이 30분마다 돈다. hq가 절약·보류 모드면 쉬고, 할 일이 없으면 **주제 후보 3개를 카드로** 올린다.
- 회장이 고르면 무료 단계(리서치 → 출처 검증 → 대본·정책 검사)를 스스로 돌린다. 대본이 나오면 검토본 페이지와 **대본 승인 카드**를 올리고, 승인하면 파이프라인의 해시 고정 승인 파일을 대신 써 준다.
- 유료 단계(음성·클립)는 팀이 돌리지 않는다. 첫 유료 실행은 회장 계정으로 `--smoke`부터 직접 해야 하기 때문이다.
- 팀 설정(`config/teams.json`)은 개인 경로가 들어가므로 git에서 제외하고 예시 파일만 공개.

**연결하자마자 찾은 버그**: 팀 카드는 펫에서 팀 캐릭터를 눌러야만 보이고, 사장 창 "내 차례"·상황 문장·알림·웹에는 빠져 있었다(상황 문장이 "지금 하실 일은 없어요"). → 팀 카드도 회장 결정 목록에 합침. 펫은 모르는 카드 종류가 와도 화면이 깨지지 않게 문자열로 읽는다.

## 2026-09-30 — 외부 구현 검토와 v4

실행 엔진 전체를 두 독립 리뷰어(두 번째 Claude 세션, 다른 모델 계열)에게 "시장에 내놓을 수준인가"로 검토받았고 **둘 다 NO SIGN**이었다. 대부분 직접 재현한 지적이었다.

**가장 무거웠던 것들**
- 샌드박스 안에서 LaunchServices로 앱을 띄우면 그 앱은 샌드박스 밖에서 실행돼 토큰을 읽을 수 있었다(재현). 목록에 없는 비밀 파일(`~/.codex` 등)도 읽히고, 사용자 Claude 세션의 메모리에 쓸 수 있었고, 남의 프로세스에 신호를 보낼 수 있었다.
- setup이 추적 파일을 바꾸면 **검사한 내용과 병합되는 내용이 달랐다**(재현).
- 수동 기준이 판정 없이 통과했고, 통합 단계에서 기존 실패가 사실상 면제됐다.
- 재시작 복구가 재사용된 pid(남의 프로세스)에 신호를 보냈고, 취소한 뒤에도 준비 중이던 작업자가 떴다.
- 팀 명령이 회장 토큰을 그대로 받아 계획·병합 카드를 결정할 수 있었다.
- 수락 직전 변경 화면이 "변경 사항이 없어요"로 나왔다(사용자 저장소에서 diff를 읽어서).

**판정과 수정** — 계약 §22에 판정을 먼저 적고, 겹치지 않는 파일 단위로 여섯 갈래를 병렬 작업자에게 맡겼다(PR #10~#16).
- 샌드박스 v4: `mach-lookup` 허용 목록(실측 2개), 홈 읽기 기본 거부, `~/.claude`는 자기 세션 폴더만, 시도별 캐시, 같은 샌드박스 안에만 신호. 공격 목록 시험 + 실제 Claude CLI 계약 시험.
- 판정: setup 뒤·검사마다 추적 파일 내용 비교, 수동 기준 검토 의무(pass/fail만), 명령 금지 규칙 원문 기준으로 통일, 통합의 기존 실패는 회장이 명시적으로 인정해야 진행.
- 프로세스: 신원(same/gone/other/unknown)이 확인된 그룹에만 신호, 모든 비동기 경계 뒤 취소 확인, 백그라운드 재시도 백오프.
- 팀: 실행마다 범위 토큰, 토큰·DB 접근 금지 프로필, 재시작 뒤 실행 이어받기.
- CLI: 잠금 파일에 신원 기록, 부분 설정 거부, 설치 표식이 있는 대상만 삭제.

**이 과정에서 내가 낸 사고 두 건**
- 새 설치를 시험하다 전역 launchd 이름 때문에 **실제 데몬을 멈추게 했다** → 설치별 이름 분리와 소유권 확인(#8)으로 이어졌다.
- 브랜치 정리 중 git이 무시 목록의 개인 설정 파일을 덮어써 데몬이 예시 경로로 돌다 죽었다 → 팀 실행 실패가 데몬을 죽이지 않게(#4).

v4 코드로 연습 저장소 요청을 다시 끝까지 돌려(계획 → 작업 → 검사 4/4 → 검토의 수동 항목 판정 → 수락 → 병합 확인 단계) 통과를 확인했다. 테스트 275개.
