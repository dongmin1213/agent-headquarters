# 0005. 이전 하네스에서 가져온 원칙

- 상태: 채택 (2026-09-29)

이전에 만들어 운영했던 멀티 에이전트 하네스의 기록에서, 개인 구독 환경에도 해당하는 것만 옮겼다.

1. **작업자·검토자의 보고를 믿지 않는다.** 실제로 "전부 통과" 보고가 틀렸던 사례, 테스트를 돌리지 않고 통과를 준 검토 사례가 있었다 → 하네스가 수용 기준을 직접 다시 실행한다. 검토 지시에는 테스트 명령·종료 코드·통과/실패 수 기록을 필수로 넣는다.
2. **종료 코드 0은 완료가 아니다.** 산출물 없이 정상 종료하는 경우가 반복됐다 → 완료 계약 파일(시도 토큰, 변경 파일 목록, 구현 커밋 + 보고서 전용 커밋, 깨끗한 작업 트리). 없으면 "확인 불가"로 두고 자동 재실행하지 않는다.
3. **검토는 새 worktree에서, 판정 값은 하네스가 주입한다.** 검토자가 해시를 잘못 옮겨 적은 사례가 있었다.
4. **지시서 오류는 오케스트레이터가 낸다.** 작업자 질문 경로와 지시서 revision을 둔다.
5. **작업자 격리 플래그로 토큰을 줄인다.** 사용자 설정·MCP를 끄면 입력 토큰이 크게 줄었다(실측 약 60%). 개인 구독 한도에서 필수.
6. **실행 방식을 바꾸는 변경은 병합 전에 실제로 한 번 돌린다.** 정적 검토는 통과했는데 실제 실행에서 결함이 나온 사례가 있었다.
7. **폭주 감시.** 한 작업자가 같은 오류로 2시간을 반복한 사례 → 시간·단계·반복 오류 상한.
8. **수락과 병합은 별개 승인.** 병합은 SHA 재확인 후 로컬에서만, push 경로 없음.
9. 원자적 파일 쓰기, 상태 폴더는 git 제외, 비밀값은 환경변수 이름만 저장, 판단 대기뿐이면 즉시 반환.

## 개인 구독이라 달라지는 점
- 한도가 CEO·작업자·사용자 세션에 공유된다 → 동시 작업자 2개, 한도 오류 관측 시 보류.
- 다른 모델 계열 교차 검토는 구독 여건상 항상 가능하지 않다 → 불가할 때는 "같은 계열 검토"로 명시한다.
