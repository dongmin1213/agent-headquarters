# 전체 표현 반려 범위와 내부 보류 보고 수정

검토자: codex. 사용자 2026-10-09 요청: 다시 멈춘 작업을 재개하고, 첨부 화면은 예시이므로 전체 화면의 낮은 품질을 수정할 것. 이어서 내부 복구 카드에 보류/중단밖에 없는 것이 유효한 사용자 결정인지 지적했다.

## 실제 중단 및 재개

HQ 데몬은 정상이며 I03 a15가 실제 정상 진행에서 B04 다리 복구 이후에도 같은 다리를 복구하라는 HUD 목표를 발견했다. product_ui.gd는 작업 소유 밖이었고 누적 복구9회와 요청당 추가 진단1회를 이미 사용해 자동 재배정이 중단됐다. 병렬 VP01은 a1/r1 반려 후 a2/r2로 UI 제작/독립 검토를 마쳤지만 이 목표 분기는 여전히 없었다.

복제 DB에서 먼저 검증 후 운영 DB before-global-presentation-1791499969.db를 백업했다. repairGameTask로 I03에 승인 VP01을 선행 추가하고 src/ui/product/product_ui.gd 한 파일만 수정 범위에 추가했다. B04 전후 정상 저장·HUD 및 목표 우선순위를 검증하며 이전 CP04 저장/관측과 아트 결과를 보존하도록 했다. 임시 중복 UI나 기존 작업자 재실행으로 대체하지 않는다. 기존 검사/독립 검토 기준은 유지했다.

실행 시도106회 사용 상태에서 남은8개 제작/검토에 최소16회가 필요했다. 사용자 재개 지시에 따라 검증된 운영자 경로로 요청 실행 상한120→124회(최소122+수정여유2)를 명시 조정했다. 무한 반복이나 상한 초기화가 아니며 모델 자동 증액은 허용하지 않는다. 이 예산 안에 품질을 달성한다는 보장은 없다.

I03 a16 pid41079가 새 지시로 실행됐고 이후 HQ/펫 갱신 뒤에도 같은 PID로 활동을 이어갔다. 확인 시 활동59건, 결정 대기0건, DB quick_check ok. 이는 재개 확인이며 게임 품질 통과가 아니다.

## 특정 예시가 아닌 전체 제품 범위

V01/Q01/A02/L02/I02/Q02/F01의 미실행 계약에 전체 화면·고유 상태·구역 목록과 실제 실행 근거를 필수 기준으로 추가했다. 타이틀부터 저장 오류·덮어쓰기·획득/상호작용·사망/보스/엔딩 등 숨은 상태까지 실제 코드에서 목록을 도출한다. 표현 밀도/명도/실루엣/카메라/지형·목적지 가독성, 텍스트와 진행 상태 일치를 점검한다. FHD/QHD 및 창/전체화면 검증도 유지한다.

공통 레이아웃 원인을 먼저 고치고 기존 양호 자산을 재사용한다. 상태별 재사용 검사 도구로 전수 확인하며 각 상태마다 전체 게임을 다시 플레이하지 않는다. 대표 정상 진행/저장 증거와 상태 주입 캡처는 구분한다. V01/Q01은 현재 후보, A02/L02는 후속 확장, Q02/F01은 최종 전체 제품에 책임을 가진다. 후속 미제작 콘텐츠를 선행 통과 조건으로 잘못 묶지 않는다. 실제 지시와 기준은 전체 plan validation 후 한 트랜잭션으로 적용했다.

## 보류 보고를 사용자 결정으로 잘못 표시한 UI 수정

기술 보류는 needsUser=false였지만 userDecisions 배열에 보고를 넣으면서 headline·펫 배지·알림이 모두 사용자 결정으로 계산했다. 이제 requiresDecision=false를 명시하고 다음을 구분한다.

- 내부 보류는 화면에 계속 표시하되 결정 대기 수에서 제외한다. 진짜 권한/선택 요청은 기존 결정으로 남는다.
- 펫 탭은 내 차례와 보고 수를 별도로 표시하고 카드/시스템 알림은 내부 처리 상황으로 표시한다. 웹도 결정과 보고 수를 구분한다.
- 내부 보고에서 요청 중단 버튼을 제거한다. 전체 요청 중단 기능 자체를 없애지는 않는다.
- 보고 확인은 기존 wire action의 읽음 처리만 사용한다. 수정 성공/재개/보류 승인으로 바꾸지 않는다. 새 발생은 다시 보고된다.
- 여유가 있을 때만 기존 비용 명시 재진단 선택을 유지하며 상한을 넘는 재진단 버튼을 만들지 않는다. 자동 복구가 멈췄다는 사실과 구체 재배정 필요성은 숨기지 않는다.

이 UI 수정만으로 모든 내부 오류가 자동 해결되는 것은 아니다. 이번 실제 결함은 위 운영자 재배정으로 별도 재개했다.

Swift6 최적화 펫 빌드 성공. 데몬 및 실제 펫(pid57302)을 갱신하고 I03 동일 프로세스 유지와 결정0건을 확인했다. 실제 새 보류 카드는 현재 재개로 사라졌으므로 운영 중 재현 화면을 생성해 시각 검사했다고 주장하지 않는다.
